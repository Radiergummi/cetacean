# Changelog entries

- One line per entry, about 25 words, never more than 40. New entries go under `[Unreleased]`.
- Write for the user: name the setting, endpoint, or page they touch, then stop.
- Leave out the reasoning, the mechanism, the old behaviour, and numbers.
- Leave out changes a user cannot notice (refactors, tests, renames, silent dependency bumps).
- Merge entries that share a subject. Only an upgrade note gets a second sentence: what the operator must do.
- Good: "Fixed the dashboard going blank when a service was removed while its detail page was open."
