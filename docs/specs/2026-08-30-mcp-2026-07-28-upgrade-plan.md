**Goal:** Move Cetacean's embedded MCP server from the `2025-11-25` profile to `2026-07-28` in full — stateless core,
the reshaped Tasks extension, MCP Apps widgets, OAuth hardening, and OpenTelemetry trace propagation — while keeping
legacy clients working.

**Architecture:** Bump `mark3labs/mcp-go` from v0.58.0 to v1.0.0-beta.1, which implements `2026-07-28` and retains the
`initialize` handshake for older clients. Most of the transport change is library-side; our work is (a) rewiring the
subscription tracking that the new `subscriptions/listen` RPC bypasses, (b) stamping cache hints on list results,
(c) hardening our own OAuth server, (d) adding an OTel adapter behind mcp-go's vendor-neutral `tracing` interfaces,
(e) building task-augmented mutations that watch Swarm converge, and (f) shipping a set of MCP Apps widgets built as a
second Vite target that reuses the existing React components.

**Tech Stack:** Go 1.25, `mark3labs/mcp-go` v1.0.0-beta.1, `go.opentelemetry.io/otel`, React 19 + Vite (widgets),
`@xyflow/react` + `elkjs` (topology graph), `@modelcontextprotocol/ext-apps` (widget-side bridge).

**Spec:** [MCP 2026-07-28 changelog](https://modelcontextprotocol.io/specification/2026-07-28/changelog);
[MCP Apps extension](https://apps.extensions.modelcontextprotocol.io/) (`2026-01-26` extension revision).

## Global Constraints

- ~~**Protocol floor stays at `2024-11-05`.**~~ **Superseded 2026-08-30 by an explicit product decision: Cetacean
  speaks `2026-07-28` and nothing else.** The MCP server shipped days before this revision and Cetacean is pre-1.0,
  so there is no installed base to carry forward, and keeping the session-based eras alive meant maintaining a
  delivery path the stateless core does not have. `requireModernProtocol` refuses older revisions at the door with
  the spec's `unsupported protocol version` error rather than serving them half-correctly. See the
  [progress log](#progress--deviation-log).
- **Output-schema validation is on server-wide** (`mcpserver.WithOutputSchemaValidation()`, shipped in the previous
  batch). Any tool that advertises a schema must produce conforming output or *every* call to it fails. Back each
  schema'd tool with a test that drives the real dispatch path — see `internal/mcp/output_schema_test.go`.
- **ACL is enforced inside handlers, never at the transport.** Every new surface (widgets, tasks, discover) must
  re-check `acl.Evaluator.Can()` with the caller's identity. Never trust a session, a widget, or a task handle as an
  authorization decision.
- **`cacheScope` is `private` for every Cetacean result.** ACL filtering makes every response identity-specific;
  `public` would let a shared intermediary serve one user's filtered view to another. This is a security constraint,
  not a performance preference.
- **No brand asset lives in the repo.** Icons are served from Cetacean itself under `/assets/`; widgets must follow
  the same rule and inline or self-host everything.
- Run `go test ./...` from the repo root. Lint with `golangci-lint run ./internal/mcp/...`. Frontend:
  `cd frontend && npx tsc -b --noEmit && npx vitest run`.
- Update `CHANGELOG.md` under `[Unreleased]` as each phase lands. Entries must be user-facing — no implementation
  detail. Sign release tags with `git tag -s`.

## Summary

The MCP server currently implements `2025-11-25` against `mark3labs/mcp-go` v0.58.0. The `2026-07-28` revision
("MCP 2.0") finalized on 2026-07-28 and is a substantially different protocol: it removes protocol-level sessions and
the `initialize` handshake, replaces `resources/subscribe` and the HTTP GET stream with `subscriptions/listen`,
introduces `server/discover`, moves Tasks and MCP Apps into a formal versioned extensions framework, and requires
cache hints on every list result.

`mcp-go` v1.0.0-beta.1 implements all of it, and — importantly — every mcp-go symbol Cetacean currently uses survives
the major bump. Verified present in v1.0.0-beta.1: `WithStateful`, `WithSessionIdleTTL`, `AddAfterSubscribe`,
`WithToolFilter`, `WithOutputSchemaValidation`, `WithHTTPContextFunc`, `WithInstructions`, `WithDescription`,
`WithResourceCapabilities`, `NewStreamableHTTPServer`. The bump is therefore mostly additive for us.

This plan covers **every** `2026-07-28` feature, plus the two extensions the product wants (Tasks, Apps), plus OTel.

## Goals

- Cetacean speaks `2026-07-28` natively and still serves `2025-11-25` and older clients.
- Agents can subscribe to live cluster changes over the new `subscriptions/listen` stream without silently getting
  nothing.
- A mutation can be issued as a task that completes when Swarm has *actually converged*, not when the API call returns.
- Agents rendering in an Apps-capable host get real interactive UI — a sortable resource table, a topology graph, a
  live log tail — instead of a wall of JSON.
- Our authorization server passes the hardened `2026-07-28` profile.
- MCP requests join the same trace as the HTTP requests around them.

## Non-goals

- Replacing the in-memory OAuth/session store ([#74]). Still the main production limitation; unchanged by this batch.
- Prompts. We expose none today and this plan adds none.
- Roots, Sampling, Logging. All three are **deprecated** in `2026-07-28`. We implement none of them and must not
  start — see [Deprecations](#deprecations-we-are-already-clear-of).
- Elicitation / MRTR. Our OAuth consent flow is a browser redirect, not protocol elicitation. No MRTR surface.

## Library gaps and risks

**G-1 — `subscriptions/listen` does not fire the subscribe hook. This is the one thing that silently breaks.**
`handleSubscriptionsListen` (`server/subscriptions.go:57`) records resource subscriptions by type-asserting the
session to `SessionWithResourceSubscriptions` — it never calls `hooks.afterSubscribe`. Our `NotificationManager`
populates its map *only* from `AddAfterSubscribe`. Worse, mcp-go's own `streamableHttpSession` does **not** implement
`SessionWithResourceSubscriptions` (only test fakes in `resource_subscribe_test.go` do), and there is no
session-factory option to substitute our own type. So on the modern path the URIs are dropped on the floor twice
over. A `2026-07-28` client would subscribe successfully, receive the acknowledgement, and then never get a single
`notifications/resources/updated`.

Mitigation is clean and needs no fork: `Hooks.AddBeforeSubscriptionsListen` / `AddAfterSubscriptionsListen` exist and
carry the full `*mcp.SubscriptionsListenRequest`, whose `Params.Notifications.ResourceSubscriptions []string` is
exactly what we need. Phase 2 wires those. Our *delivery* path is unaffected — `subscriptionAllowsNotification`
fails open for sessions that implement no filter interface, so our own fan-out still reaches the client.

**G-2 — v1.0.0-beta.1 is a beta.** Decide before merging whether a beta dependency may appear in a tagged Cetacean
release. Options: (a) land the batch on `feat/mcp-2026-07-28` and hold the merge until mcp-go v1.0.0 final;
(b) ship it and pin exactly. This plan assumes (a) — develop now, gate the release on final. **Flagged for the user;
not decided in this document.**

**G-3 — no `ui://` helper types in mcp-go.** MCP Apps metadata rides the generic `mcp.Meta.AdditionalFields`. That is
sufficient (the extension is pure `_meta` + a resource), but it means we own the field names and must test the wire
shape rather than lean on the compiler. Phase 11 adds a typed wrapper of our own so the names are declared once.

## Deprecations we are already clear of

Verified by grep across `internal/mcp/` — Cetacean implements **none** of these, so the deprecation window costs us
nothing and no migration work is needed:

| Deprecated in `2026-07-28` | Our exposure |
|---|---|
| Roots | none — no `roots/list`, no `notifications/roots/list_changed` |
| Sampling | none — we never call `sampling/createMessage` |
| Logging (`logging/setLevel`, `notifications/message`) | none — we log to `slog`, never over the protocol |
| HTTP+SSE transport | none — streamable HTTP only |
| `includeContext: thisServer` / `allServers` | none — no sampling |

```go
func (nm *NotificationManager) SubscribedURIs(sessionID string) []string {
	nm.mu.RLock()
	defer nm.mu.RUnlock()

	st := nm.sessions[sessionID]
	if st == nil {
		return nil
	}

	uris := make([]string, 0, len(st.uris))
	for uri := range st.uris {
		uris = append(uris, uri)
	}

	return uris
}
```

```go
	// 2026-07-28 replaced resources/subscribe with subscriptions/listen, which
	// does not fire the subscribe hooks above: mcp-go records those URIs by
	// type-asserting the session to SessionWithResourceSubscriptions, and its
	// streamable-HTTP session does not implement that interface. Track them
	// here instead, or modern clients would subscribe successfully and then
	// never receive a single notification.
	h.AddBeforeSubscriptionsListen(
		func(ctx context.Context, _ any, msg *mcplib.SubscriptionsListenRequest) {
			sid := sessionIDFromContext(ctx)
			if sid == "" {
				return
			}

			identity := auth.IdentityFromContext(ctx)
			for _, uri := range msg.Params.Notifications.ResourceSubscriptions {
				s.notifications.Subscribe(sid, uri, identity)
			}
		},
	)

	// The listen handler blocks until the client disconnects, so the after-hook
	// is our stream-closed signal. Drop exactly what this request established;
	// the session may still hold subscriptions from another listen stream.
	h.AddAfterSubscriptionsListen(
		func(ctx context.Context, _ any, msg *mcplib.SubscriptionsListenRequest, _ *mcplib.SubscriptionsListenResult) {
			sid := sessionIDFromContext(ctx)
			if sid == "" {
				return
			}

			for _, uri := range msg.Params.Notifications.ResourceSubscriptions {
				s.notifications.Unsubscribe(sid, uri)
			}
		},
	)
```

```go
// Cache TTLs advertised on list and read results (SEP-2549). They are freshness
// hints, not correctness guarantees: a client may serve a cached list for this
// long before re-fetching. Both are deliberately short — Cetacean mirrors live
// cluster state, and an agent acting on a minute-old service list can scale the

const (

// would be an authorization bypass.
func applyCacheHints(result *mcplib.CacheableResult, ttl time.Duration) {
	if result == nil {
		return
	}

	result.SetCacheHints(ttl.Milliseconds(), mcplib.CacheScopePrivate)
}
```

```go
// Package tracing adapts OpenTelemetry to the vendor-neutral tracing interfaces
// mcp-go exposes. mcp-go deliberately depends on no tracing SDK; this package
// is the bridge, so the OTel dependency stays confined to one file.
package tracing

import (
	"context"

	mcpgotracing "github.com/mark3labs/mcp-go/tracing"
	"go.opentelemetry.io/otel/attribute"
	"go.opentelemetry.io/otel/codes"
	"go.opentelemetry.io/otel/propagation"
	oteltrace "go.opentelemetry.io/otel/trace"
)

type otelTracer struct {
	tracer oteltrace.Tracer
}

// NewOTelTracer wraps an OpenTelemetry tracer for use by mcp-go.
func NewOTelTracer(tracer oteltrace.Tracer) mcpgotracing.Tracer {
	return otelTracer{tracer: tracer}
}

func (t otelTracer) Start(
	ctx context.Context,
	name string,
	kind mcpgotracing.SpanKind,
	attrs ...mcpgotracing.Attribute,
) (context.Context, mcpgotracing.Span) {
	ctx, span := t.tracer.Start(ctx, name,
		oteltrace.WithSpanKind(spanKind(kind)),
		oteltrace.WithAttributes(attributes(attrs)...),
	)

	return ctx, otelSpan{span: span}
}

type otelSpan struct {
	span oteltrace.Span
}

func (s otelSpan) SetAttributes(attrs ...mcpgotracing.Attribute) {
	s.span.SetAttributes(attributes(attrs)...)
}

func (s otelSpan) RecordError(err error) { s.span.RecordError(err) }
func (s otelSpan) End()                  { s.span.End() }

func (s otelSpan) SetStatus(code mcpgotracing.StatusCode, description string) {
	switch code {
	case mcpgotracing.StatusError:
		s.span.SetStatus(codes.Error, description)
	case mcpgotracing.StatusOK:
		s.span.SetStatus(codes.Ok, description)
	default:
		s.span.SetStatus(codes.Unset, description)
	}
}

func spanKind(kind mcpgotracing.SpanKind) oteltrace.SpanKind {
	switch kind {
	case mcpgotracing.SpanKindServer:
		return oteltrace.SpanKindServer
	case mcpgotracing.SpanKindClient:
		return oteltrace.SpanKindClient
	default:
		return oteltrace.SpanKindInternal
	}
}

func attributes(attrs []mcpgotracing.Attribute) []attribute.KeyValue {
	out := make([]attribute.KeyValue, 0, len(attrs))
	for _, a := range attrs {
		out = append(out, attribute.String(a.Key, a.Value))
	}

	return out
}

// metaCarrier adapts an MCP _meta property bag to the TextMapCarrier the W3C
// propagator expects. SEP-414 reuses the W3C key names (traceparent, tracestate,
// baggage) verbatim, so no key translation is needed.
type metaCarrier map[string]any

func (c metaCarrier) Get(key string) string {
	if v, ok := c[key].(string); ok {
		return v
	}

	return ""
}

func (c metaCarrier) Set(key, value string) { c[key] = value }

func (c metaCarrier) Keys() []string {
	keys := make([]string, 0, len(c))
	for k := range c {
		keys = append(keys, k)
	}

	return keys
}

type otelMetaPropagator struct {
	propagator propagation.TextMapPropagator
}

// NewOTelMetaPropagator returns a propagator that carries W3C trace context
// through an MCP request's _meta, per SEP-414.
func NewOTelMetaPropagator() mcpgotracing.MetaPropagator {
	return otelMetaPropagator{
		propagator: propagation.NewCompositeTextMapPropagator(
			propagation.TraceContext{},
			propagation.Baggage{},
		),
	}
}

// InjectMeta writes the active span context into meta.AdditionalFields. Per the
// interface contract it allocates a Meta when meta is nil and there is
// something to write, and returns nil when the result would stay empty — the
// common case of an untraced request must not grow an empty _meta.
func (p otelMetaPropagator) InjectMeta(ctx context.Context, meta *mcp.Meta) *mcp.Meta {
	carrier := metaCarrier{}
	p.propagator.Inject(ctx, carrier)

	if len(carrier) == 0 {
		return meta
	}

	if meta == nil {
		meta = &mcp.Meta{}
	}
	if meta.AdditionalFields == nil {
		meta.AdditionalFields = make(map[string]any, len(carrier))
	}

	maps.Copy(meta.AdditionalFields, carrier)

	return meta
}

// ExtractMeta reads traceparent/tracestate/baggage back out of _meta, so a tool
// call joins the trace of whatever issued it.
func (p otelMetaPropagator) ExtractMeta(ctx context.Context, meta *mcp.Meta) context.Context {
	if meta == nil || len(meta.AdditionalFields) == 0 {
		return ctx
	}

	return p.propagator.Extract(ctx, metaCarrier(meta.AdditionalFields))
}
```

Note the signature: `MetaPropagator` operates on `*mcp.Meta`, **not** a bare map — it is
`InjectMeta(ctx, *mcp.Meta) *mcp.Meta` and `ExtractMeta(ctx, *mcp.Meta) context.Context`. Add `"maps"` and
`mcp "github.com/mark3labs/mcp-go/mcp"` to the imports.

## Phase 10 — Tasks extension: converging mutations ([#70])

**Why this is now worth building.** The previous batch deferred Tasks because mcp-go ran the *same* handler
asynchronously: our write handlers return as soon as the Docker API accepts the change, so a task would complete
instantly and tell the agent nothing. The `2026-07-28` extension changes the shape — `tasks/result` (blocking) is
replaced by polling `tasks/get`, `tasks/list` is gone, and **servers may return a task handle unsolicited**. That
lets us return a handle immediately and complete it only when the cache shows Swarm has actually converged. This is
the single highest-value MCP feature for an agent operating a cluster: *"scale this and tell me when it is really
running"*.

```go
package mcp

import (
	"context"
	"fmt"
	"time"

	"github.com/radiergummi/cetacean/internal/cache"
)

// convergencePollInterval is how often a running task re-checks the cache. The
// cache is in-memory and the predicate is a cheap read, so this is bounded by
// how quickly we want to notice convergence, not by cost.
const convergencePollInterval = 500 * time.Millisecond

// convergenceFunc reports whether the cluster has reached the state a mutation
// asked for. status is a human-readable progress line surfaced through
// tasks/get so a polling client can show what is happening.
type convergenceFunc func(ctx context.Context, c *cache.Cache) (done bool, status string)

// awaitConvergence blocks until fn reports done or ctx expires. Docker's write
// APIs return as soon as the swarm accepts a spec change, long before the new
// state is real; this is what turns "accepted" into "actually running".
func (s *Server) awaitConvergence(ctx context.Context, fn convergenceFunc) error {
	ticker := time.NewTicker(convergencePollInterval)
	defer ticker.Stop()

	// Check once before waiting: an already-satisfied mutation should not pay
	// a full tick.
	if done, _ := fn(ctx, s.cache); done {
		return nil
	}

	for {
		select {
		case <-ctx.Done():
			return ctx.Err()

		case <-ticker.C:
			if done, _ := fn(ctx, s.cache); done {
				return nil
			}
		}
	}
}

// serviceConverged reports a replicated service as converged once its running
// task count matches its desired replica count and no update is in progress.
func serviceConverged(serviceID string) convergenceFunc {
	return func(_ context.Context, c *cache.Cache) (bool, string) {
		svc, ok := c.Service(serviceID)
		if !ok {
			return false, "service not found in cache yet"
		}

		desired := uint64(0)
		if svc.Spec.Mode.Replicated != nil && svc.Spec.Mode.Replicated.Replicas != nil {
			desired = *svc.Spec.Mode.Replicated.Replicas
		}

		running := uint64(0)
		for _, task := range c.TasksForService(serviceID) {
			if task.Status.State == swarm.TaskStateRunning {
				running++
			}
		}

		// An in-flight rolling update means the spec changed again; wait it out
		// rather than reporting a transient match as success.
		if svc.UpdateStatus != nil && svc.UpdateStatus.State == swarm.UpdateStateUpdating {
			return false, fmt.Sprintf("rolling update in progress (%d/%d running)", running, desired)
		}

		if running == desired {
			return true, fmt.Sprintf("converged: %d/%d replicas running", running, desired)
		}

		return false, fmt.Sprintf("waiting: %d/%d replicas running", running, desired)
	}
}
```

- [ ] **Step 4: Write the host bridge**

Create `frontend/src/widgets/bridge.ts` — a typed wrapper over the postMessage JSON-RPC dialect. Use
`@modelcontextprotocol/ext-apps` if adding the dependency is acceptable; otherwise implement the handful of methods
directly. The surface the widgets need:

```ts
/**
 * The subset of the MCP Apps host bridge Cetacean's widgets use.
 *
 * Widgets never call Cetacean's HTTP API directly — every read goes through
 * callTool, so the host mediates it and the server applies the caller's ACL
 * grants on the one audited path.
 */
export type HostBridge = {
  /** Invoke an MCP tool on the Cetacean server and resolve its structured content. */
  callTool: <T>(name: string, args: Record<string, unknown>) => Promise<T>;
  /** Register a callback for tool results the host pushes into the widget. */
  onToolResult: <T>(callback: (result: T) => void) => () => void;
  /** Ask the host to change display mode. */
  requestDisplayMode: (mode: "inline" | "fullscreen" | "pip") => Promise<void>;
  /** Report the widget's content size so the host can resize the iframe. */
  notifySize: (width: number, height: number) => void;
  /** The host's current theme, so widgets match the surrounding client. */
  theme: "light" | "dark";
};

/**
 * Performs the ui/initialize handshake and resolves once the host is ready.
 */
export async function connectHost(): Promise<HostBridge> {
  const pending = new Map<number, { resolve: (value: unknown) => void; reject: (error: Error) => void }>();
  const toolResultListeners = new Set<(result: unknown) => void>();

  let nextId = 1;
  let theme: "light" | "dark" = "light";

  function send<T>(method: string, params: Record<string, unknown>): Promise<T> {
    const id = nextId++;

    return new Promise<T>((resolve, reject) => {
      pending.set(id, { resolve: resolve as (value: unknown) => void, reject });
      window.parent.postMessage({ jsonrpc: "2.0", id, method, params }, "*");
    });
  }

  window.addEventListener("message", ({ data }) => {
    if (data?.jsonrpc !== "2.0") {
      return;
    }

    // A response to something we sent.
    if (data.id !== undefined && pending.has(data.id)) {
      const entry = pending.get(data.id);
      pending.delete(data.id);

      if (data.error) {
        entry?.reject(new Error(data.error.message ?? "host call failed"));
      } else {
        entry?.resolve(data.result);
      }

      return;
    }

    // A notification pushed by the host.
    switch (data.method) {
      case "ui/notifications/tool-result":
        for (const listener of toolResultListeners) {
          listener(data.params?.structuredContent ?? data.params);
        }
        break;

      case "ui/notifications/host-context-changed":
        if (data.params?.theme === "light" || data.params?.theme === "dark") {
          theme = data.params.theme;
        }
        break;
    }
  });

  await send("ui/initialize", {
    protocolVersion: "2026-01-26",
    capabilities: {},
    clientInfo: { name: "cetacean-widget", version: "1" },
  });

  return {
    callTool: async <T,>(name: string, args: Record<string, unknown>): Promise<T> => {
      const result = await send<{ structuredContent?: T }>("tools/call", { name, arguments: args });

      // Cetacean tools always return structuredContent (output schemas are
      // validated server-side), so prefer it and fall back only defensively.
      return (result.structuredContent ?? result) as T;
    },

    onToolResult: <T,>(callback: (result: T) => void) => {
      toolResultListeners.add(callback as (result: unknown) => void);

      return () => {
        toolResultListeners.delete(callback as (result: unknown) => void);
      };
    },

    requestDisplayMode: async (mode) => {
      await send("ui/request-display-mode", { mode });
    },

    notifySize: (width, height) => {
      window.parent.postMessage(
        { jsonrpc: "2.0", method: "ui/notifications/size-changed", params: { width, height } },
        "*",
      );
    },

    get theme() {
      return theme;
    },
  };
}
```

The `"*"` target origin is what the MCP Apps transport specifies — the host assigns each app its own opaque origin
(`_meta.ui.domain`), and the iframe cannot know the parent's origin ahead of time. Isolation comes from the sandbox,
not from the target-origin check. Validate the *shape* of every inbound message (as above) rather than its origin.

Method names on the wire, from the MCP Apps extension: `ui/initialize`, `tools/call`, `ui/request-display-mode`,
`ui/notifications/size-changed`, `ui/notifications/tool-result`, `ui/notifications/host-context-changed`.

### 2026-08-30 — Phase 8 (CIMD-first posture) landed; Batch B complete

things the write-up assumed were already fine.

- **RFC 9207 `iss`** on both authorize redirects. The success path sets it beside `code`; the error path needed
  `redirectWithError` to become a method on `*Server`, since it is where the issuer lives. Every call site moved with
  it. Covered by driving the real consent flow (GET for the CSRF token and nonce cookie, then POST approve/deny) and
  reading `iss` off the `Location` header, rather than unit-testing the query builder.
- **`application_type`** on DCR (SEP-837), defaulting to `native`. Validated *before* the `client_id` is minted,
  because it decides which redirect URIs are acceptable — a `web` client may not register a loopback URI. Five tests:
  the default, an explicit echo, an unknown value, the loopback rejection, and the native-loopback case that is the
  whole reason the default is `native`.

Deviation from the plan: it specified adding an `isLoopbackRedirect` helper, but `isLoopbackURI` already exists in
`dcr.go` and is what `isValidRedirectURI` uses. Reused it rather than adding a second spelling of the same predicate.

Phase 8 (CIMD-first posture) is next in Batch B and is mostly documentation; `client_id_metadata_document_supported`
still needs checking against the AS metadata struct.

### 2026-08-30 — legacy protocol support removed

Product decision by the user, overriding this plan's first Global Constraint: Cetacean now implements `2026-07-28`
and refuses everything older. The reasoning is that the MCP server shipped days before the revision and the project
is pre-1.0, so there is no installed base worth the cost — and the cost was real, because the two eras need
different notification-delivery paths and only one of them is exercised.

mcp-go offers no minimum-version option — it will negotiate down to `2024-11-05` through `initialize` — so the
refusal is ours: `requireModernProtocol` (`internal/mcp/protocol_gate.go`) sits innermost in the handler chain, after
the origin and bearer checks so an unauthenticated caller learns nothing. A compliant modern request always carries
`Mcp-Protocol-Version` (mcp-go rejects one that declares its version only in `_meta`), so the header alone is a
sufficient and cheap test and the accepted path never reads the body. Rejections carry the spec's
`UnsupportedProtocolVersionError` — code `-32022`, naming `2026-07-28` in `data.supported` — and echo the request id
so a client can correlate them. A request carrying `Mcp-Session-Id` is refused too, since honouring it would
resurrect the path that was just removed.

`server/discover` now advertises only `2026-07-28`, via `mcpserver.WithSupportedProtocolVersions` on the request
context. Without it mcp-go listed all five revisions it implements, which would have sent a well-behaved client
straight into a rejection it was told to expect to work.

Removed as a consequence:

- `WithStateful(true)` / `WithSessionIdleTTL` → `WithStateful(false)`; there is no session state to keep.
- `CETACEAN_MCP_SESSION_IDLE_TTL` and `CETACEAN_MCP_MAX_SESSIONS`, their `[mcp]` TOML keys, and the config plumbing
  and tests behind them. A leftover value is ignored rather than fatal — the TOML decoder is not strict and unknown
  env vars are simply unread — which a test now pins, so an existing deployment's config keeps working.
- The `resources/subscribe` / `resources/unsubscribe` hooks (those RPCs no longer exist), the `OnUnregisterSession`
  hook (nothing registers a session any more), the session-registry delivery branch, `legacySessions()`, and the
  `SendNotificationToAllClients` broadcast. `NotificationManager` now serves exactly one era, and every session it
  holds reached it through `subscriptions/listen`.
- The legacy test helpers `initSession` / `mcpJSONRPC` / `mcpJSONRPCWithToken`, plus the tests that asserted legacy
  behaviour. Every remaining test drives the modern path; `TestInitializeAdvertises…` became
  `TestDiscoverAdvertises…`, reading `serverInfo` from the result `_meta` where `2026-07-28` moved it.

**This closes [E-3] as well**, in the sense that it is now the only thing left in that area: the `tasks` and `ui`
extensions are still advertised without being wired, and that is still wrong on the wire. It was not part of this
change and remains open for a decision.

**E-2 — Phase 2 does not work in production. The bug it was written to fix is still present.**
Found by review after Batch A was committed; verified end-to-end, not theorised.

`installSubscriptionHooks` keys everything on `sessionIDFromContext(ctx)` and bails when it is empty. For a
2026-07-28 client it is *always* empty: `handleRequest` leaves `sessionID` as `""` for modern requests
(`server/streamable_http.go:641-648` — "The Mcp-Session-Id header is ignored, and no session ID is minted"), so
`streamableHttpSession.SessionID()` returns `""` and both new hooks return without recording anything.

Reproduced by driving `subscriptions/listen` through the real handler: the client gets **HTTP 200 and a
`notifications/subscriptions/acknowledged` frame echoing its `resourceSubscriptions`**, while
`NotificationManager` holds no session at all. That is precisely the [G-1](#library-gaps-and-risks) failure mode
the phase exists to prevent — subscribe succeeds, then silence.

The Phase 2 unit tests pass because they invoke the hook funcs directly with a synthetic
`stubSession{id: "session-modern"}`; the stub supplies the one thing the real transport never provides. The phase
was verified at the wrong altitude: `cachehints_test.go` argues the opposite principle in its own comment ("a unit
test on the constants alone would not catch an unwired server option") and drives the real handler.

The gap is one layer below the hooks, so the fix is not another hook. Delivery also goes through
`SendNotificationToSpecificClient(d.sessionID, …)`, which resolves a session out of mcp-go's registry by ID — for a
modern client there is no registered ID to resolve. `NotificationManager` must be keyed on something that exists on
the modern path (the `mcpserver.ClientSession` value, which mcp-go itself uses for delivery, or the subscription
ID), and modern delivery must write to that session rather than look one up by ID. The legacy path keeps working
either way, since a registered session has both an ID and a value.

**Resolved.** `NotificationManager` is now keyed on the `mcpserver.ClientSession` value rather than on a session-ID
string, which is the one identity that exists on both protocol eras. `sessionState` also records the
`SubscriptionFilter` the listen stream established, so the opt-in rule is enforced per session. Delivery splits on
the same fact: a session carrying an ID is addressed through mcp-go's registry exactly as before, and a session
without one is written to directly — SSE upgrade, then a non-blocking send, mirroring what mcp-go does internally.
Teardown drops the whole record on stream close, because a modern session is ephemeral to its request.
`sessionIDFromContext` is gone; nothing keys on the ID any more.

Verified end-to-end in `internal/mcp/subscriptions_e2e_test.go`, which runs a real `httptest` server, holds a
`subscriptions/listen` stream open, mutates the cache, and reads `notifications/resources/updated` back off the
stream. Re-introducing the original `if sid == "" { return }` makes that test fail, so it genuinely covers the
regression. Legacy delivery and the era difference in list_changed opt-in are pinned by their own tests, and the
whole package passes under `-race`.

**E-4 — `CETACEAN_MCP_CIMD_ENABLED` was never read.** Found during Phase 8.

`config.MCPConfig.CIMDEnabled` was parsed, defaulted, documented in `CLAUDE.md` and `docs/mcp.md`, and covered by a
config test — but no code in `internal/mcp/oauth` ever consulted it. `resolveClientMeta` chose the CIMD path on
`strings.HasPrefix(clientID, "https://")` alone, so setting it to `false` changed nothing.

This is worse than a dead setting. CIMD makes the server issue an outbound HTTPS request to a URL the *client*
supplies; the SSRF blocklist bounds where that can go, but an operator who turns CIMD off is removing that surface
entirely, and was silently not getting it. Fixed in Phase 8: the flag is checked before the fetch, and the AS
metadata only advertises CIMD when it is on, so the document cannot promise a path the server refuses.

**E-3 — The extensions advertised in Phase 5 are not merely unimplemented, they are wrong on the wire today.**
Upgrades [E-1](#issues-encountered-running-log), which recorded this as deferred debt.

`mcpserver.WithExtensions` only writes `capabilities.extensions`. Enabling Tasks is a *separate* option,
`mcpserver.WithTaskCapabilities(list, cancel, toolCallTasks)`, which we never call — and
`server/request_handler.go` gates every `tasks/*` method on `capabilities.tasks != nil`, returning
`METHOD_NOT_FOUND`. So a host reads `io.modelcontextprotocol/tasks` from `server/discover`, calls `tasks/list`, and
is told tasks are unsupported. The `ui` entry has the same shape: we advertise
`mimeTypes: ["text/html;profile=mcp-app"]` while no resource declares that MIME type.

**Resolved 2026-08-30.** Both entries are dropped until the phases that wire them: `serverExtensions()` returns an
empty map, and [Phase 10](#phase-10--tasks-extension-converging-mutations-70) and
[Phase 11](#phase-11--mcp-apps-foundation-ui-resources--widget-build) each re-add theirs alongside
`WithTaskCapabilities` and `registerUIResources` respectively. The constants stay, since those phases consume them.

Guarding it by removal alone would just invite the same drift later, so the replacement is behavioural.
`TestTasksExtensionMatchesWiring` probes `tasks/get` and fails if the advertisement and the capability disagree;
`TestUIExtensionMatchesWiring` scans `resources/list` for a resource declaring `uiMIMEType` and does the same. Both
fail in *either* direction — advertising what is not wired, and wiring what is not advertised — so neither phase can
land half of its change, and neither test needs editing when they do. Verified by re-adding both entries and
confirming each test fails with a message naming the missing half.
